# Benchmarking genomic imputation in a non-model system (demo pipeline)

**Motivating question (from project brief):** BEAGLE, STITCH, and GLIMPSE were developed
and validated on human and crop reference panels. Non-model outbreeding species (e.g.
white clover, *Trifolium repens*) typically have lower effective population size, lower
genome-wide diversity, and lower recombination rates. Does imputation performance, and
its sensitivity to reference panel size and sequencing depth, transfer to that regime?

## What this demo does

Since no real *T. repens* reference panel or low-coverage sequencing data was available
to me at prototyping time, this project simulates data with the relevant evolutionary
genetic properties and implements the **Li & Stephens (2003) haplotype-copying HMM** —
the statistical model underlying BEAGLE, IMPUTE, GLIMPSE, and STITCH — from scratch in
NumPy, then benchmarks its imputation accuracy across a grid of reference panel sizes and
target sequencing depths.

This demonstrates the core skills the real project needs:
- Understanding of coalescent/haplotype-copying models and how reference-panel imputation
  actually works algorithmically (not just "call a tool")
- Ability to simulate genomic data with tunable population-genetic parameters
  (recombination rate, panel size, allele frequency spectrum)
- Designing and running a benchmarking sweep with proper held-out ground truth
- Producing clear, quantitative accuracy metrics (genotype concordance, dosage r²) and
  visualizations

## Files

| File | Purpose |
|---|---|
| `simulate_data.py` | Founder-mosaic coalescent-style simulator for a reference panel + held-out target haplotypes, with a low recombination rate parameterized to reflect a non-model species |
| `run_imputation_benchmark.py` | From-scratch Li-Stephens forward-backward HMM imputation engine + benchmark sweep over depth × panel size |
| `plot_results.py` | Generates the heatmap and line-plot figures in `results/` |
| `results/` | CSV of benchmark results + figures (generated by running the scripts) |

## How to run

```bash
python3 simulate_data.py               # sanity-check the simulator
python3 run_imputation_benchmark.py    # runs the full benchmark, writes results/benchmark_results.csv
python3 plot_results.py                # writes results/heatmap_dosage_r2.png, results/concordance_vs_depth.png
```

## Key result (from the included run)

Imputation accuracy (dosage r²) increases steeply with reference panel size and shows
strong diminishing returns from additional sequencing depth once panel size is adequate
— e.g. at a 200-haplotype panel, going from 0.5x to 4x depth barely moves accuracy
(0.994 → 0.998 r²), whereas going from a 20- to 200-haplotype panel at fixed 1x depth
improves r² from 0.69 to 0.99. This mirrors a real, actionable finding for study design:
**for a low-recombination, low-diversity species, investment in a larger reference panel
may pay off more than investing in higher target sequencing depth.**

## Honest limitations / what the real project would add

- Real reference panels are not literal founder mosaics — this is a simplified stand-in
  for a coalescent process, chosen so ground truth is always exactly known.
- The HMM here is haploid (per-haplotype), matching GLIMPSE's phased-panel approach;
  a full project would also benchmark BEAGLE's and STITCH's own diploid/unphased models
  by actually installing and running those tools on the real white clover panel and VCFs,
  and comparing their accuracy/runtime against this reference implementation.
- Recombination rate, mutation/error rate, and the founder-mosaic diversity model are
  simplifications; a real analysis would estimate or take these from the species' actual
  linkage map and SFS.
